Why localhost sometimes looks stuck — read this once

CampusHood is three programs talking to each other, all running on your own machine. When the page hangs, it's almost always one of these three, not "the internet":

uvicornThe Python server — the brain. If this window shows an error and stops, the page has nothing to talk to. Always check this terminal first.
OllamaThe local AI model. Only wakes up when you open "Ask the agent." First reply after a restart takes ~15–20s while it loads into memory — that's normal, not broken.
SQLite databaseOne file (campuspool_demo.db) holding every user, ledger row and audit entry. "Reset the seed" just rewrites this file to a known starting point.

Everything you see on screen — the ₹500 proposal, the policy verdicts, the audit rows — is uvicorn reading that one SQLite file and handing JSON to the browser. Nothing is computed in JavaScript; the frontend only displays numbers the server already decided. That's the whole claim of the product, and it's also why the tamper demo in Scene 6 works: edit the file directly, and the app itself notices.

Before you roll

  1. Open PowerShell in the project folder and activate the environment, then reset the demo data to a clean, known state so the video always starts the same way. cd "C:\Users\Vaibhav Mishra\OneDrive\Desktop\razopay" .venv\Scripts\activate python -m backend.seed.demo_data --reset
  2. Start Ollama in its own window and warm the model — do this before you hit record, so Scene 4 doesn't sit on a 20-second cold load. ollama serve ollama run qwen2.5:7b-instruct "hi" Wait for a reply, then you can close that second command — the model stays warm in memory.
  3. Start the app server in a third window and leave it running for the whole recording. uvicorn backend.main:app --port 8000 Watch for the line Application startup complete. If it errors instead, read the traceback — it'll usually name a missing package fixed with pip install -r requirements.txt.
  4. Open 127.0.0.1:8000/app in Chrome. Set the user picker (top right) to Aarav — he already has a goal, ledger history and a mid-cycle pool position, so the story reads immediately instead of an empty new account.
  5. Open a second Chrome tab, keep it on about:blank — you'll navigate it to the audit trail section for Scene 6 without losing your place in the first tab.
  6. Say the synthetic-data line once, at the very top, then never again: every number is fake, every payment is Razorpay test mode. Repeating it later reads as nerves, not rigor.

Scene 54:20 – 5:05

The record can't be forged quietly

Do

Switch to your terminal window.

sqlite3 campuspool_demo.db "UPDATE audit_events SET action='intent:POLICY_CHECK->ALLOWED' WHERE seq=1;"
Do

Switch back to the Audit trail tab and refresh. The chain pill turns red and names the row.

Say
"Each entry commits to the hash of the one before it. I just rewrote history with direct database access — the strongest attacker there is — and the system named the exact row. This doesn't make the log immutable; nothing in one database can. It makes tampering impossible to do silently."
Do

Restore it live, so it's clear this was a deliberate break, not a bug:

python -m backend.seed.demo_data --reset

If something breaks mid-take

Chat hangs a long timeModel's cold or the machine's loaded. Say so on camera: "that's a 7B model on a laptop — here's the same thing in the benchmark at 21ms with the model removed," and keep going. Don't stop the take to debug.
Checkout won't openCheck 127.0.0.1:8000/health/ready in a spare tab — it names the missing piece in one line.
A tab shows stale numbersRefresh — state polls every 15s but a manual refresh is instant and looks intentional on camera.
You forgot to reseed after the tamper demoJust say it: "that's the last take's tamper still showing — which is rather the point." Then reseed and re-take Scene 6 only.
Server won't start at allRead the last line of the traceback in the uvicorn window — it's almost always ModuleNotFoundError, fixed by pip install -r requirements.txt in the activated venv.
